高级配置

启用缓存
缓存到期前自动按历史参数重新查询回填
开启后，网关每次请求的参数组合会被记住；后台定时检查缓存剩余时间， 快过期时自动重新查询写回缓存，用户请求时始终命中缓存。 需要先开启「缓存」（预热就是把结果提前写进缓存），并且需要 Redis 已启用。
跨日停止：每天 0 点起暂停，当天有新请求才恢复
开启后，0 点之后昨天那批参数不再被预热，直到当天有真实请求进来才恢复。 适合「今天没人用的参数就别白跑」的场景，避免陈旧参数空耗数据库。
立即清空该 API 的所有缓存，同时清除已记录的预热参数。
预热始终以历史请求参数为底（这样不同 supplierId 等业务参数各自都能预热到）， 这里只列出需要被刷新的字段。
支持多组：写成数组即可按多个时间段各缓存一份，例如近1日/近7日/近30日：
[{"startTime":"${T_1}"},{"startTime":"${T_7}"},{"startTime":"${T_30}"}]
其它参数保持历史请求原值，最终预热组合数 = 历史参数组合数 × 覆盖组数。
为什么需要：历史请求里的时间是写死的（如 2026-08-17）， 明天拿它去预热就是在预热过期数据。把时间字段用 ${变量} 覆盖后， 每轮预热实时求值成当前时间，业务字段则保持原样。 变量在「项目页 → 环境变量」里维护。
启用限流
开启：调用必须携带 API Key；关闭：公开访问

数据同步配置

把外部推送的数据写进数据源表（写入类接口，仅超管）
⚠ 这是本系统唯一的「写库」接口：调用会真实修改数据源里的数据。 只有超级管理员能创建和修改；调用走 xpftkey（与普通 API 一致）。
⚠️ 持有该 API Key 的人就能往目标表写数据，请按写权限的标准保管：不要对外散发、不要写进前端代码、定期轮换。
只有登记在这里的表名和字段才允许写入 —— 表名/字段名无法参数化，白名单是唯一的防注入手段。 格式：{"表名": ["字段1", "字段2"]} 
POST <上方的调用地址>
Header: xpftkey: <项目或API的Key>

{
  "tableName": "order_table",
  "pkId": ["order_id"],
  "data": [
    {"order_id": 121212, "order_name": "测试订单"}
  ]
}
写入规则：按 pkId 先查该行是否存在 —— 存在则 UPDATE，不存在则 INSERT。 pkId 可以是多个字段（联合判重）。
出错处理：逐条写入，遇到错误就停下，已写入的保留， 返回 failedIndex（失败行号）、failedReason、failedRow 便于定位补数。

Python 插件

用 Python 脚本作为 API 逻辑，需定义 main(params, ctx)
⚠ 安全提示：插件代码会在服务器上执行任意 Python（可 import 第三方库、访问网络与数据库）。 这不是安全沙箱，仅限可信成员编写。请勿粘贴来源不明的代码。
必须定义 def main(params, ctx): 并 return 结果（list/dict/标量，会被 JSON 序列化）。
ctx 能力：
· ctx.params — 本次调用参数（dict）
· ctx.query(datasource, sql, params) — 查指定数据源，返回 list[dict]（自动参数化，禁 DDL）
· ctx.http — requests 模块，调外部 HTTP
· ctx.log(msg) — 写一条服务端日志
· ctx.vars — 临时读写空间（dict）
普通参数 → :参数名 值走参数化绑定(防注入)。数组值自动展开 IN：id IN :ids 或 id IN (:ids) 均可。
嵌套取值 → :{路径} 循环里取子字段：$for(ch in channels)$ ... :{ch.channelName} ... $endfor$，中文/任意字符安全。
结构插值 → #{名称} 仅用于表名/列名/排序方向，只允许字母数字下划线；值类数据一律用左边两种。
{#
复杂参数(array / object)#} {# 点参数行的「结构」定义内部字段，即可：自动生成嵌套测试参数、执行前按路径校验必填(如 channels[0].prdId)。
#}
