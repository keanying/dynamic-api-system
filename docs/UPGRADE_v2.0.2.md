## 一、新功能

### 1. 嵌套参数 + `:{表达式}` 安全绑定插值（解决多渠道 union all 场景）

入参可以是任意嵌套 JSON。典型场景 —— 按渠道分组统计：

**请求体：**
```json
{
  "channels": [
    { "channelName": "抖音", "prdId": ["476855"] },
    { "channelName": "美团", "prdId": ["476897", "476898"] }
  ],
  "merchant_id": 37950206,
  "start_time": "2024-12-25 00:00:00",
  "end_time":   "2024-12-26 00:00:00"
}
```

**SQL 模板写法：**
```sql
$for(ch in channels)$
select sum(case when spu_id in (:{ch.prdId}) then pay_count else 0 end) as pay_count,
       :{ch.channelName} as channel
from report.r_report_dwm_common
WHERE merchant_id = :merchant_id
  AND operated_at >= :start_time
  AND operated_at < :end_time
$sep$
union all
$endfor$
```

**实际执行的 SQL（值全部参数化绑定，防注入）：**
```sql
select sum(case when spu_id in (%(__tpl_b0__0)s) then pay_count else 0 end) as pay_count,
       %(__tpl_b1)s as channel
from ...
union all
select sum(case when spu_id in (%(__tpl_b2__0)s, %(__tpl_b2__1)s) then ...) as pay_count,
       %(__tpl_b3)s as channel
from ...
```

要点：
- `:{表达式}` 里可以写任何模板表达式：`:{ch.channelName}`、`:{ch.prdId}`、`:{ch.prdId.0}`
- 值是 **list 时自动 IN 展开**，`in (:{ch.prdId})` 和 `in :{ch.prdId}` 两种写法都行
- 值走 prepared statement，中文、引号、任意字符都安全（对比 `#{}` 只允许标识符类字符）
- 支持 modifier：`:{ch.name}|like` 自动加 `%` 并转义
- `$if` / `$for` / `defined()` / `len()` 中也都支持点路径：`$if(len(ch.prdId) > 0)$`

### 2. SQL 中英文冒号不再冲突（可以停用全角冒号的变通做法）

现在占位符识别是**字面量感知**的：`'...'`、`"..."`、`` `...` ``、`--`、`#`、`/* */` 内的英文冒号一律原样保留，不会被当成 `:param`：

```sql
SELECT DATE_FORMAT(operated_at, '%H:%i')  AS hh,     -- 字符串里的 : 和 % 都安全
       ':literal_colon'                    AS s,
       json_col->'$.a'                     AS j        -- '{"a":{"b":1}}' 这类 JSON 也安全
FROM t WHERE id = :id                                   -- 真正的占位符照常工作
```

- 附带修复：字符串里的字面 `%`（如 `DATE_FORMAT` 的 `%H`、`LIKE '%x%'` 手写模式）自动转义，不再触发 pymysql `unsupported format character` 报错；**已手写 `%%` 的历史 SQL 保持原样**。
- 极端场景下若在字符串之外需要字面冒号，可写 `\:xxx` 转义（执行前还原为 `:xxx`）。
- **历史 SQL 里已使用的中文全角冒号 `：` 完全不受影响**，可以继续用，也可以逐步改回英文冒号。

### 3. GET 请求参数按类型自动转换（修复遗留 bug）

原网关代码里类型转换被**误写死在 `/weibo/comment`** 这一个 API 上（且每个 GET 请求都会多查一次库、`bool("false")` 还会错误地转成 `True`）。现已改为：引擎按**实际命中的 API 自己的参数定义**做宽松转换：

- `number` → int/float；`boolean` → `"true"/"1"` 为真、`"false"/"0"` 为假；`array`/`object` → JSON 解析
- 转换失败保留原值不报错（数据库侧通常也能隐式转换），对存量调用零冲击
- `/weibo/comment` 行为不变（转换逻辑等价），其他所有声明了类型的 GET API 同时受益

## 二、修复与加固（不改变对外行为）

| 项 | 说明 |
|---|---|
| Redis 缓存连接复用 | 原实现每次缓存读/写/清都新建 TCP 连接再关闭，高 QPS 下产生大量 TIME_WAIT；改为共享客户端（自带连接池） |
| 结果集序列化性能 | `format_as_json` 原来对每个非 dict 单元格（含 datetime/Decimal）都尝试 `json.loads` 并打 warning，一次万行查询刷上万条告警；现只对 str/bytes 尝试，**解析结果与历史行为完全一致**（含 `"123"→123`） |
| 内存缓存上限 | 新增 5000 条上限 + 过期/最早过期淘汰，防止长期运行内存无限增长 |
| IN 展开上限 | 数组超过 10000 个元素直接报错，防止超大数组把 SQL 撑爆（DoS 防护）；正常业务不受影响 |
| `IN ((a,b))` 行构造器坑 | `IN (:ids)` 写法现在会吸收原括号，不再生成 MySQL 报错的双括号 |
| DDL 拦截绕过 | `/*注释*/DROP ...`、`-- 注释\nDELETE ...` 这类前导注释绕过已拦截；`SELECT update_time` 等列名不误伤 |
| API Key 比较 | 改为常量时间比较（`secrets.compare_digest`），防时序侧信道 |
| HTML API 标题转义 | `_build_html_page` 的 `<title>` 做 HTML 转义 |
| JWT | `create_jwt_token` 不再原地修改调用方传入的 payload dict |

## 三、明确未改动的部分（保障存量）

- 数据库模型 / 表结构：**零变更**，无需迁移
- 数据源密码的 XOR 加密方案：**保持不变**（改动会导致存量已加密密码无法解密；如需升级到 AES，需要单独做一次全量重加密迁移，建议后续版本处理）
- 已有模板语法（`$if/$elseif/$else/$for/$sep`、`:name`、`:name|like*`、`#{name}`、IN 展开、空数组 `(NULL)`、默认值/必填校验）：全部保持原语义，56+ 项回归测试通过
- 全角冒号 `：`、手写 `%%`：原样保留
- 管线模式 / 插件模式：自动继承以上所有能力（共用 `_parse_sql_params`）

## 四、已知边界（写模板时注意）

1. `:{}` 不要写在 SQL 字符串字面量**内部**（引号里的 `:{}` 会原样保留，这是为了不误伤 JSON 字面量）
2. `#{}` 依旧只允许 `[A-Za-z0-9_,. *]`，用于表名/列名/排序方向；**值类数据一律用 `:name` 或 `:{expr}`**
3. 极端情况：`$if$/$for$` 指令如果把一个 SQL 字符串字面量从中间切开，字面量识别以渲染后的整体 SQL 为准（正常写法不会遇到）
4. MySQL 8 的 `WITH ... DELETE` 形式 CTE 写法不在 DDL 前缀拦截范围内 —— 根治方案是给数据源账号只授 SELECT 权限（强烈建议生产数据源使用只读账号）

# v2.5.1 增量说明（静态资源缓存 + 主子参数配色）

## 1. 静态资源缓存失效（重要，解决"更新后界面还是旧的"）

`style.css` / `app.js` 等静态资源此前无版本号，浏览器会长期缓存，导致更新代码后仍显示旧界面（例如参数树还是旧的竖排样式）。现在页面链接自动带上版本号 `?v=<文件修改时间>`，文件一变版本号就变，浏览器自动拉取最新——**以后升级不用再手动清缓存**。

> 若个别浏览器仍显示旧界面，强刷一次（Ctrl+F5 / Cmd+Shift+R）即可，之后就正常了。

## 2. 主参数 / 子参数配色区分

- 普通主参数：白底。
- 复杂主参数（Object/Array，可展开）：淡蓝底强调，「结构」按钮展开时变实心蓝。
- 子参数区：蓝色渐变卡片 + 左侧强调条，与主参数明显区分；每个子参数行是白底卡片，悬停有描边高亮；越往下嵌套底色越浅，层级一目了然。
- 子参数输入框底色比主参数浅一档，聚焦时蓝色高亮。

# v2.7 增量说明（线上功能回归修复 —— 重要）

## 1. 历史 API 调不通（"未找到匹配的 API"）—— 已修复

**问题**：网关匹配 API 时强制要求 `status == 'online'`，而存量/历史 API 的生命周期 `status` 可能是 `draft`/空/NULL（例如 status 列在更早版本已存在、未被"存量置 online"的迁移覆盖到），导致这些本来能用的 API 全部返回 `5003 未找到匹配的 API`。

**修复**：网关改为「`is_enabled=True` 且 `status != 'offline'`（含 NULL）即可对外调用」，保证历史 API 不被误伤。真正的下线用 `is_enabled=False` 或 `status='offline'` 表达。已验证 `draft` 状态 API 可正常路由到执行。

## 2. 全部 API 请求都要有日志 —— 已确认/加固

网关每个出口路径（IP 拦截、项目不存在、API 未找到、Key 校验失败、HTML 渲染、SQL/管线执行成功或失败）都会写一条 `CallLog`。已实测：成功、404（API 未找到）、404（项目不存在）、Key 失败等场景全部落库，`call_source` 区分 gateway/test。

## 3. 全系统时间统一为北京时间 UTC+8 —— 已修复

新增 `app/core/timezone.py`，提供 `now()/today_start()/days_ago()`（均返回北京时间 naive datetime）。所有 ORM 时间默认值（`created_at`/`updated_at` 等）、仪表盘"今日调用"、"今日调用分布"按小时归桶、"近 N 天"趋势、慢查询/日志清理边界，全部改用北京时间。

> 存量数据说明：升级前的记录按 UTC 存储，升级后新记录按北京时间存储，二者有 8 小时口径差；日志类数据会随时间滚动，短期内新数据即为正确的北京时间。如需彻底纠正历史数据，可对存量 `created_at` 统一 `+8 小时`（按需单独执行，本次未自动改写历史数据以免误伤）。

## 4. API 调用兼容性 —— 已多场景验证

GET/POST、带参数、需/不需 API Key、draft/legacy 状态、嵌套参数等场景均验证可路由可执行、可记录日志。

# v2.8 增量说明（启动备份 + 预发布 pre 环境隔离）

## 1. 启动自动备份（每次启动都执行）

每次应用启动，自动把「正式表」的核心数据导出为可直接回灌的 SQL(INSERT) 文件，
存到项目根目录 `backup/` 下，文件按启动时刻命名（`backup_YYYYMMDD_HHMMSS.sql`），
同名直接覆盖。

- 备份范围：用户 `src_dop_users`、项目 `src_dop_projects`、API `src_dop_api_configs`
  及其参数 `src_dop_api_parameters`、数据源 `src_dop_datasources`。
- 备份始终针对正式表（无 `_pre` 后缀），无论当前跑 pre 还是正式 —— 要保护的是正式数据。
- 备份失败不阻断启动（仅告警）。`backup/` 已加入 `.gitignore`。

恢复方式：SQL 文件是标准 INSERT 语句，可直接在数据库执行回灌（按需先清空目标表）。

## 2. 预发布 pre 环境隔离（同库不同表名）

用命令行参数区分环境，正式数据与测试数据物理隔离：

- **正式环境**（默认）：`python main.py`，表名无后缀。
- **预发布环境**：`python main.py --env pre`，所有表名加 `_pre` 后缀
  （如 `src_dop_api_configs_pre`），与正式表在同一个库、互不影响。

pre 环境启动时的数据同步：
- `_pre` 表由建表逻辑按当前模型自动创建（字段最新，无需迁移）。
- **仅当某张 `_pre` 表为空时**，才从对应正式表同步一份数据过去；
  `_pre` 表已有数据则保留不动（避免冲掉正在测试的改动）。

这样：首次跑 pre 会得到一份正式数据副本用于验证；你在 pre 里怎么改都不碰正式表；
测试通过后再用 `python main.py`（正式环境）上线。

判定优先级：命令行 `--env pre` 优先；其次环境变量 `APP_ENV=pre`
（uvicorn reload/多进程 spawn 子进程时靠环境变量兜底，main.py 已自动透传）。

实现要点：新增 `app/core/runtime_env.py`（环境判定 + 表名后缀 `t()`）、
`app/core/backup.py`（备份 + pre 同步）；`models.py` 的 `__tablename__`、`ForeignKey`、
具名 `Index` 全部走 `t()` 加后缀；pre 环境跳过正式表的列自动迁移（`_pre` 表本就是最新结构）。

> 注意：pre 与正式共用一个数据库连接配置（config.yaml 的 database.url），仅靠表名后缀隔离。
> 若希望更强隔离（独立库），可另行为 pre 配置单独的 database.url。


## 修订：备份/同步 SQL 的 MySQL 兼容（v2.8.1）

初版 backup.py 用双引号包表名（`SELECT * FROM "src_dop_users"`），SQLite 合法但 **MySQL 会报 1064 语法错误**。已改为跨库标识符引用 `_qi()`：MySQL 用反引号 `` ` ``、SQLite 用双引号，备份与 pre 同步在 MySQL 下正常执行。导出的备份 SQL 文件用反引号，可直接回灌 MySQL。


## 修订：删除参数不即时刷新（v2.8.2）

删除顶层参数后页面无反馈、需保存刷新才更新。根因：`delNode` 删除顶层参数后仍调用 `syncTopParam(旧索引)`，此时该索引已指向别的参数或 undefined，读取 `_schema` 抛异常，导致后续 `renderParamTree()` 未执行。已修正：顶层删除不再对已删索引做同步，`syncTopParam` 增加 undefined 兜底。删除顶层/子参数、删空均即时刷新。
